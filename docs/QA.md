### 임베드 환경 (다른 페이지 안에 넣었을 때)

엄격한 보안 정책을 흉내 낸 로컬 서버로 `dist/` 와 `dist-embed/` 를 각각 시험했습니다.
조건: `connect-src 'self'` (blob: fetch 차단), WebAssembly 차단, 게임패드 권한 차단, localStorage 접근 시 예외.

| 막힌 기능 | 게임의 동작 |
|---|---|
| blob: fetch | GLB 내장 텍스처를 `<img>` 로더로 읽음 (`core/assets.ts`) |
| WebAssembly | 적 LOD 를 건너뛰고 원본 메시 사용 |
| 게임패드 | 한 번 실패하면 다시 묻지 않음. 키보드·터치는 그대로 |
| localStorage | 세이브·설정·랭킹 없이 진행 (새로 고치면 처음부터) |

결과: 타이틀 → 프롤로그 → 낮 → 밤 전투까지 진행. 콘솔에는 blob: 가능 여부를 확인하는 요청이 막혔다는 경고만 남습니다.

claude.ai 아티팩트로 올린 페이지 자체는 개발 환경에서 열어 볼 수 없어 **실제 뷰어에서의 동작은 확인하지 못했습니다.**

## 배포 뒤 보고된 문제

### 밤에 화면이 검게 변함 (새벽이 시작될 때) — 수정함

- **증상**: 밤 전투 중 3D 화면만 검게 변하고 HUD 는 그대로 보임.
- **원인**: 가로등 빛 원뿔 셰이더(`night/map.ts`)가 `pow(vUv.y, 1.6)` 을 계산했는데, 삼각형 가장자리 픽셀에서는 보간된
  `vUv.y` 가 0 보다 살짝 작아질 수 있다. 음수의 `pow` 는 GLSL 에서 정의되지 않은 동작이라 GPU 에 따라 NaN 이 나온다.
  HDR 버퍼에 NaN 픽셀이 **하나**만 있어도 블룸의 흐림 필터가 화면 전체로 퍼뜨려 전부 검게 된다.
- **왜 테스트에서 못 잡았나**: 개발 환경의 SwiftShader 는 이 경우 NaN 을 내지 않는다. 화면을 그리는 백엔드가 하나뿐이었다.
- **재현**: Chrome 을 Mesa llvmpipe 로 띄우니 재현됐다. 수정 전에는 중간 품질(MSAA)에서 가로등이 화면에 있는 **모든 프레임**이,
  높음 품질에서는 다섯 프레임에 한 번꼴로 검었다. 프레임마다 메시를 하나씩 숨겨 보며 원인 메시를 찾았다.
- **조치**
  1. 원인 셰이더 수정: `pow(clamp(vUv.y, 0.0, 1.0), 1.6)`.
  2. 같은 종류의 위험을 전부 정리: 각성 오라의 프레넬 `pow`, 뒤집힌 `smoothstep` 6곳, 중심점의 `atan(0, 0)`.
  3. 방어선 추가(`vfx/postfx.ts`): 블룸 입력과 색보정 입력에서 NaN·Inf 를 0 으로 바꾼다. 앞으로 어떤 머티리얼이 이상한 값을 내도
     한 픽셀로 끝난다. 일부러 NaN 을 주입한 테스트(`--inject`)에서 검은 프레임 0 을 확인했다.
- **수정 후**: llvmpipe 중간·높음 품질 모두 NaN 0, 검은 프레임 0. 같은 지도를 쓰는 밤거리 컷씬도 함께 고쳐졌다.
- **실제 GPU 에서 확인 (2026-11-19, AMD Radeon 860M · Chrome ANGLE D3D11 · 중간 품질, GitHub Pages 배포본)**
  - 수정한 빌드: 보스 등장 → 싸움 → 새벽 → 귀가 461프레임에서 검은 프레임 0, NaN 0 (HDR 버퍼 154회 검사).
  - 같은 자리에서 가로등 셰이더만 수정 전으로 되돌리면 NaN 픽셀이 다시 나온다: 싸움 중 91회 검사 가운데 28회, 새벽 44회 가운데 32회.
    새벽에 더 자주 나오는 것이 "새벽이 시작될 때 검게 변한다"는 보고와 맞는다.
  - 이때도 방어선 덕분에 화면은 검게 되지 않았다(검은 프레임 0).

## 사람이 직접 해 봐야 하는 것 (자동 테스트로 확인 못 함)

- **실제 GPU 에서의 fps.** 개발 환경에는 GPU 가 없습니다. 실제 GPU 로는 위의 검은 화면 검사 한 번(타이틀 화면 약 125fps, AMD Radeon 860M)만 해 봤고, 적이 많은 구간의 fps 는 재지 않았습니다. F3 으로 확인해 주세요.
- **소리.** 헤드리스 환경에는 오디오 출력이 없어 BGM·효과음의 음량 균형과 타격음 느낌을 귀로 확인하지 못했습니다. 코드 경로(재생, 크로스페이드, 음량 설정)만 오류 없이 도는 것을 확인했습니다.
- **타격감의 체감.** 히트스톱·흔들림·넉백 수치는 스크린샷과 프레임 캡처로만 확인했습니다. `src/data/feel.json` 으로 조절합니다.
- **게임패드와 진동.** 이동, 레벨업 카드 선택(좌우 + A), Start 일시정지를 구현했지만 실제 패드로는 시험하지 못했습니다.
- **실제 휴대폰.** 844×390 화면과 합성 터치 이벤트로 가상 조이스틱 이동을 확인했습니다. 실제 기기의 성능·발열·사파리 동작은 미확인입니다.

## 개발 중 찾아서 고친 문제

### 진행이 막히거나 화면이 깨지던 것

| 문제 | 원인 | 조치 |
|---|---|---|
| 밤 지형이 통째로 안 그려짐 | 바닥 셰이더에서 GLSL 예약어 `patch` 를 변수명으로 사용 | 변수명 변경 |

## 알려진 한계

- 적과 보스의 그림자는 둥근 블롭입니다. 실시간 그림자는 높음 품질에서 개와 지형·소품에만 적용됩니다.
- 낮 행동 연출은 행동마다 짧은 장면(이동 + 애니메이션 + 이펙트)입니다. 사람 캐릭터에 "쓰다듬기" 같은 전용 동작은 없어 비슷한 동작으로 대신했습니다.
- 개 모델(여우)에는 걷기·달리기·서 있기 세 가지 애니메이션만 있습니다. 눕기·앉기·짖기는 자세 보정과 이펙트로 표현했습니다.
- BGM 4곡은 Web Audio 로 합성한 짧은 반복 곡입니다.
- 세이브는 브라우저 localStorage 에만 저장됩니다. 랭킹은 로컬 상위 10개입니다.
- 컷씬 카메라는 실시간 트윈이라, 프레임이 크게 떨어지는 기기에서는 컷이 끊겨 보일 수 있습니다(스킵 가능).
