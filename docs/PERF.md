# 성능 리포트

측정일 2026-11-17 · three.js r187 · `npm run build` (minify) 결과물 기준

## 먼저 알아둘 것: 실제 GPU 에서의 fps 는 재지 못했습니다

개발 환경의 Chrome 은 GPU 없이 소프트웨어(SwiftShader)로 그립니다. 여기서는 화면이 초당 3~15장밖에 안 나오므로
"60fps 가 나온다"는 것을 **직접 확인하지 못했습니다.** 아래 수치는 GPU 와 무관하게 잴 수 있는 것들입니다.

- 시뮬레이션(CPU) 비용: 한 틱에 걸리는 시간
- 그리기 부하: 드로우콜 수, 삼각형 수
- 메모리, 번들 크기, 로딩 시간

실제 기기에서는 게임 안에서 **F3** 을 누르면 fps · 업데이트/렌더 시간 · 드로우콜 · 삼각형 수가 나옵니다.
60fps 가 안 나오면 설정에서 품질을 한 단계 낮추세요.

## 밤 전투 (7번째 밤, 무기 5종 보유, 1280×720)

`node tests/perf.mjs [low|medium|high]` 로 다시 잴 수 있습니다. 적 수를 강제로 맞춘 뒤 300틱을 돌린 값입니다.

- 60fps 의 한 프레임은 16.7 ms 입니다. 적 450마리에서도 게임 로직은 1 ms 안팎이라 **CPU 는 병목이 아닙니다.**

- 실제 플레이에서 봇이 기록한 동시 적 수 최대치는 밤에 따라 50~300마리였습니다(`tests/balance.mjs`).

## 남은 개선 여지

- **실제 기기 프로파일링.** 내장 그래픽 노트북과 휴대폰에서 F3 수치를 보고 `quality.json` 기본값을 다시 잡아야 합니다.
- **높음 품질은 적 메시를 원본 그대로** 씁니다(450마리에서 236만 삼각형). 외장 GPU 를 전제로 한 설정입니다.
- **메시·텍스처 압축 없음.** Draco/Meshopt 지오메트리 압축과 KTX2 를 쓰면 에셋 11.2 MB 를 절반 이하로 줄일 수 있습니다(gltf-transform 필요).
- **캐릭터 GLB 중복.** 사람 캐릭터 4종이 같은 애니메이션을 각자 들고 있습니다. 리그를 공유하면 2 MB 이상 줄어듭니다.
- **코드 분할 없음.** 밤 전투·컷씬 코드까지 `app.js` 하나에 들어 있습니다. three.js 가 대부분이라 분할 이득은 크지 않습니다.
- **화면 밖 적도 그립니다.** 적은 대부분 화면 안으로 모여들기 때문에 인스턴스 단위 컬링은 넣지 않았습니다.
